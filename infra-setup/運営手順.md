## 5. 設定変更のやり方（必要になったとき）

### 5-1. ユーザーを消す
Admin パネルから削除（Hub の DB から消える）。Linux ユーザーとホームは残るので、消すなら VM で
`sudo userdel -r jupyter-<id>`（**成果物が消える。慎重に**）。削除スクリプトは事故防止のため置いていない。

### 5-2. ユーザー毎の上限を変える（無停止）
```
sudo tljh-config set limits.memory 2G
sudo tljh-config set limits.cpu 2
sudo tljh-config reload hub
```
反映されるのは**その後に起動したサーバーだけ**。動作中の人は Admin パネルで Stop → 本人が再 Start。

### 5-3. VM のサイズを変える（停止が必要・URL は不変）
55 人 × 2GB = 110GB は現 VM（64GB）を超えるので、上限を 2G にするなら VM も上げる。
```
gcloud compute instances stop fx-tljh --project=fx-itnern --zone=asia-northeast1-b
gcloud compute instances set-machine-type fx-tljh --project=fx-itnern --zone=asia-northeast1-b --machine-type=e2-highmem-16
gcloud compute instances start fx-tljh --project=fx-itnern --zone=asia-northeast1-b
```
その後 5-2 で `limits.memory 2G`。`config.sh` と `04` の値も合わせて直す。

### 5-4. 収容人数の目安（現行 e2-highmem-8 / 128GB）
| | 55 人最大時 | 上限 |
|---|---|---|
| メモリ | 55GB | 64GB（OS+Hub 約 3GB） |
| ディスク | 110GB | 128GB（OS+TLJH 約 8GB） |
| CPU | — | 同時に重い処理 8 人まで快適 |

### 5-5. app/DB VM（fx-trade-api-ssd）の負荷とスケールアップ

**観測（2026-09-02 リハーサル中）**: 1 人が `proceed_to_end()`（約 64 req/s、15.7ms/step）を回すだけで
app コンテナが 1 コアの約 75% を消費した。現行 e2-medium（2 vCPU / 4GB）では**全力実行できるのは同時 2〜3 人**。
50 人が一斉に 1,440 tick を回すと 1 人あたりの完走が 30 秒 → 数分以上に伸びる見込み。
メモリ（1.1/3.8GB）・ディスク（25%）・DB 接続数には余裕があり、**ボトルネックは app の CPU のみ**。

**対策**: イベント当日だけスケールアップする（例: e2-standard-8 = 8 vCPU、約 $0.4/時）。
外部 IP は静的予約済み・内部 IP も VM 削除まで不変なので、参加者向け URL も TLJH の `FX_API_BASE_URL` もそのままでよい。

```
gcloud compute instances stop fx-trade-api-ssd --project=fx-itnern --zone=asia-northeast1-b
gcloud compute instances set-machine-type fx-trade-api-ssd --project=fx-itnern --zone=asia-northeast1-b --machine-type=e2-standard-8
gcloud compute instances start fx-trade-api-ssd --project=fx-itnern --zone=asia-northeast1-b
```

**⚠️ 起動後の必須作業**: docker-compose.yml に restart ポリシーが無いため**コンテナは自動起動しない**。必ず実行:

```
gcloud compute ssh fx-trade-api-ssd --project=fx-itnern --zone=asia-northeast1-b \
  --command='sudo docker compose --project-directory /home/ky2001/fxtrade-api up -d && sleep 5 && curl -sf http://localhost:8000/health'
```

イベント後は同じ手順で e2-medium に戻す（**戻し忘れると差額が常時課金**され続ける）。
