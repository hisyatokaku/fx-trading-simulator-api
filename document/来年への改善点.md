# 来年への改善点（2026-09 イベントの振り返り）

最終更新: 2026-09-11

## 1. リポジトリを private にする

**現状の問題**
- フォークは単独で private にできない。`data/scenarios.csv` に EVAL の日付、`data/rates.csv` に当日のレートが入っており、GitHub を見れば答えが取れる。
- 一度 public だった履歴はクローンやキャッシュに残り得るので、private 化は「今後の露出を減らす」対策。過去分の取り消しにはならない。

**手順（自分で完結する方法）**
1. 現フォークを `fx-trading-simulator-api-fork` などに改名する
2. 元の名前で private リポジトリを新規作成する
3. ローカルから `git push --mirror` で全ブランチ・タグを移す
4. GitHub Actions のシークレット（GCP 認証）を新リポジトリに再登録する
5. 未マージ PR を再作成する（PR と Issue の履歴は移らない）
6. ローカルの `git remote set-url`、WebUI リポジトリの README リンク、運営手順の URL を更新する
7. 古いフォークを削除する（archive では public のまま残る）

**注意**
- private では Actions の無料枠が月 2,000 分。deploy は e2e テストのタイムアウト待ちで毎回 5 分以上使うので、先に e2e を直す
- 上流へ PR を戻す予定が無いことを確認しておく
- 別案: GitHub サポートに「Detach fork」を依頼すれば PR 履歴ごと残せるが、数日かかる

## 2. `fetch_rates_to_jpy` / `fetch_rates_for_last_n_ticks` が EVAL で黙って空を返す

**何が起きたか**
- 2 関数は `GET /api/rate/{timestamp}` を使う。サーバは EVAL 期間の時刻を 403 で拒否する（事前に答えを読めないようにする仕様）。
- 関数は 200 以外をすべて `{}` にして返し、エラーも警告も出さない。
- あるチームが「戦略の初期レート（過去 n tick）」をこの関数で取る実装のまま本番提出した。TEST では正常に動いていたが、EVAL では履歴が空のまま走り、戦略が想定どおり働かないまま 1 回限りの提出が確定した。
- 教材にこの制約が書かれておらず、docstring も「無い場合は空」としか書いていない。

**対処案（組み合わせる）**
1. 教材に明記: 該当関数の docstring と「本番提出」の説明に「EVAL 期間では 403 になり空を返す。本番で使えるレートは `next` の応答だけ」と書く
2. 関数側で 403 を区別してメッセージを表示する
3. 解答例を「開始前レートに依存しない」形にする（最初の n tick は観測に使い、それから取引する）
4. 運営ルールとして、この事故を「再提出を認める」対象にするか事前に決めておく（認めるなら該当チームの完走セッション削除が必要）

**根本的な選択肢**
- 「開始前の履歴は見られない」こと自体を教材の前提に組み込む（推奨）
- あるいは、セッション開始時にサーバが直前 n tick 分のレートを応答に含める設計にする。参加者が事前取得 API を叩く必要が無くなる

## 3. app の自動起動
- VM 再起動後に docker compose を手で上げる運用。compose に `restart: unless-stopped` を付けるだけで解消する。
